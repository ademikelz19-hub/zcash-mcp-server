## Detailed Step-by-Step Script

### Scene 1: The Problem (0:00 - 0:30)
**Visual:** Split screen: Code editor on left, AI chat on right.  
**Narrator:**  
> "As AI coding assistants build more web3 applications, they frequently introduce catastrophic privacy leaks: defaulting to transparent addresses, including cleartext emails in on-chain memos, or hardcoding test keys.  
> Here is a typical payment config generated by an AI assistant: it uses a transparent `t1` address and includes a customer's email in the memo."

**Code Displayed (`fixtures/vulnerable_app/config.json`):**
```json
{
  "recipient": {
    "address": "t1VpYecBW4UudbGcy4ufh61eWxQCoFaUrPs",
    "memo": "Please confirm order 1042 for user alice@cypherpunk.org"
  }
}
```

---

### Scene 2: The Detection (0:30 - 0:55)
**Visual:** Run ZecShield audit via MCP.  
**Prompt in AI Assistant:**
> *"Run ZecShield Privacy Firewall audit on this payment configuration before broadcast."*

**Command / MCP Call:**
```python
audit_transaction_privacy(
    address="t1VpYecBW4UudbGcy4ufh61eWxQCoFaUrPs",
    amount_zec="50.0",
    memo_utf8="Please confirm order 1042 for user alice@cypherpunk.org"
)
```

**Firewall Output:**
```json
{
  "verdict": "BLOCKED_BY_FIREWALL",
  "privacy_score": 20,
  "is_safe_to_broadcast": false,
  "findings": [
    {
      "id": "ZEC-PRIV-001",
      "name": "TRANSPARENT_ADDRESS_EXPOSURE",
      "severity": "CRITICAL",
      "remediation": "Switch recipient to a ZIP 316 Unified Address with shielded receivers."
    },
    {
      "id": "ZEC-PRIV-002",
      "name": "PII_EMAIL_IN_MEMO",
      "severity": "CRITICAL",
      "remediation": "Remove email from memo fields or use zero-knowledge commitments."
    }
  ]
}
```
**Narrator:**
> "ZecShield immediately intercepts the transaction pre-broadcast. It flags two CRITICAL violations: transparent address graph exposure, and cleartext email PII. It drops the privacy score to 20/100 and fails closed."

---

### Scene 3: The Fix (0:55 - 1:20)
**Visual:** Developer updates the address to a canonical ZIP 316 Unified Address and blinds the memo.  
**Command / MCP Call:**
```python
audit_transaction_privacy(
    address="u1wujllpw6w6vg6tdn0m700vsysch7vm3zlgru509nutav65s6ucw9rkgkm5u4tsq2up43z3zr5h6ympsj2p9ta2anzv076rjlgj8t5pknjd5hxn2pkrjmr4uj9a2n8c5xclw4y8zk5uvn4j44548z84ty55ldcp0ugxnps2pjp7cqflwp955wsxwkr50u897nx427l2fn4vcejrfhljw",
    amount_zec="50.0",
    memo_utf8="REF: 5a8e0f9b31d2c47a // Blinded Hash Commitment"
)
```

**Output:**
```json
{
  "verdict": "PERMITTED",
  "privacy_score": 100,
  "is_safe_to_broadcast": true,
  "summary": { "total_findings": 0, "critical": 0 }
}
```
**Narrator:**
> "With a canonical Unified Address and a blinded cryptographic reference, the transaction passes with a perfect 100/100 score. It is now safe to broadcast."

We never fabricate blocks and claim they were mined by Zebra."

### Scene 5: The AI Privacy Boundary (1:55 - 2:20)
**Visual:** Inspect MCP tool responses returned to the AI assistant.  
**Narrator:**
> "Notice what the AI model sees when querying transaction history. Memos are strictly redacted: `[REDACTED_BY_ZECSHIELD_FOR_AI_PRIVACY]`. Spending keys and seeds never touch model context. Spending requires an out-of-band human authorization token. The AI can prepare and audit payments, but cannot steal funds or exfiltrate private note data."
